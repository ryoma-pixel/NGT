# NGT 手配ボード（台帳）第2版

予約からガイド手配・完了までを、1つのスプレッドシートで管理する仕組みです。共有アカウント（info_ninja-go-ride@ninja-kabukitokyo.com）の Google スプレッドシート・フォーム・ドライブ・Gmail の上で動き、追加の費用はかかりません。

2026-11-16 に株式会社Kiranah Resort 加藤様と決めた仕様で作り直しました（第1版の「通知メールの取り込み」と「入力画面」は使いません）。

## 1日の流れ

| 時刻 | だれが | やること | 台帳では |
|---|---|---|---|
| 12:00 | キラナ | LINKTIVITY から「本日以降の確定予約」の CSV を2つ書き出し、置き場フォルダに入れる（またはメニュー「CSVを取り込む」で選ぶ） | 新しい予約は「新規（受注待ち）」、CSV から消えた予約は「キャンセル」で出る。キラナとリールにお知らせメール |
| 13:00 | リール | 「対応一覧」を見る。新規に ①受注 ✓ | 「受注済み（手配中）」 |
| 前日20:00まで | リール | ガイドを決め、ガイド名を入れて ②手配完了 ✓ | 「手配済み（ゲスト連絡待ち）」 |
| 連絡がとれ次第 | リール（ガイド） | ③ゲスト連絡 ✓ | 「ゲスト連絡済み」 |
| ツアー後 | ガイド | ④の「報告フォーム」で完了報告を送る（リンクはリールからガイドへ） | 「完了報告済み（受領待ち）」 |
| 報告後 | キラナ | 報告を読んで ⑤受領 ✓ | 「完了」 |

- **前日20:00に未手配**なら、キラナとリールに【至急】メールが届き、台帳は「未手配（期限切れ）」（赤）になる。キャンセルの手続きは手配ボードの外で行う（手配ボードは知らせるだけ）。キャンセルされると次のCSVで「キャンセルが発生しました」に出る。
- 19:00 に、翌日分の未手配があれば先に知らせる。
- **キャンセル**：CSV から消えた予約（今日以降の分）はキャンセルとして出る。対応一覧の「本日のキャンセル」に出て、リールが受注済みなら「キャンセルが発生しました」として「キャンセル確認（リール）」に ✓ するまで残る。台帳では取り消し線が付く。
- **メール・インフルエンサーの予約**：メニュー「予約を手入力する（メール・インフルエンサー）」の画面で、経路・催行日・開始・ツアー・人数・代表者名・連絡先を入れて登録する。案件IDは自動で付き、リールの受注待ちになる（台帳の空いている行に直接書いてもよい）。
- **手配の目安**：前日20:00は「期限」（過ぎたら原則キャンセル）。余裕のある予約は、催行の3日前の20:00を「目安」にする。目安を過ぎると対応一覧で黄色になり、19:00のお知らせに入る（キャンセルにはしない）。日数は設定シートの「手配の目安（何日前）」、0で使わない。
- **③ゲスト連絡**は、リールでもガイドでも ✓ してよい（色は青緑）。

## シートの見方

- **対応一覧**：リールがやること・キラナがやることを期限順に並べたもの。赤は期限切れ。「台帳で開く」でその行へ飛ぶ。
- **台帳**：1件1行。左の「次にやる人・次にやること・期限・状態」はスクリプトが書く（オレンジ＝リール、青＝キラナ、緑＝ガイド、赤＝期限切れ）。見出しの色：紺＝予約の内容、オレンジ＝リールが ✓、青＝キラナが ✓、緑＝ガイド。
- **ツアー**：PLAN名からツアーを判定するキーワード、時刻の読み替え（NKTセットは 15:00→16:30、18:00→19:30）、完了報告の選択肢になる行程。
- **設定**：通知先・期限など。
- **完了報告**：フォームの回答がここにたまる。台帳の「報告の要約」にも1行で入る。
- **ログ**：取り込み・✓・報告の記録。

## 期限（設定シートで変えられる）

| 段階 | 期限 | 過ぎたら |
|---|---|---|
| ①受注 | CSV を取り込んだ後の最初の 13:00 から60分（14:00） | キラナとリールにメール |
| ②手配完了 | 催行の前日 20:00（目安は3日前の20:00） | 期限：「未手配（期限切れ）」と【至急】メール／目安：黄色と19時のお知らせ |
| ③ゲスト連絡 | 開始の3時間前（**仮置き**） | メール |
| ④完了報告 | 催行日の翌日 12:00 | メール |
| ⑤受領 | 報告から3日 | メール |
| キャンセル確認 | キャンセルが出てから3時間 | メール |

- 期限切れのメールは、同じ案件・同じ段階で1回だけ。夜間（22:00〜8:00）は送らず、朝にまとめる。
- 完了報告で「合流できなかった」「トラブルがあった」「反応が2以下」のときは、すぐに【至急】で知らせる。

## 完了報告フォーム（ガイド用）

台帳の ④ 列に、案件ごとのリンク（案件IDとツアーが入った状態で開く）が出ます。リールからガイドに渡してください。

- **必須（マスト）**：ゲストと合流できたか／予定の行程をすべて回ったか／終了時刻／注意事項を説明したか／ケガ・トラブル・苦情の有無／ゲストの反応（5段階）／レビューのお願い（その場で書いてもらった・お願いした・お願いできなかった）／（あった場合）その内容
- **任意（ウォント）**：いちばん盛り上がった場所・時間が押した場所（ツアーの行程から選ぶ）／写真をお渡ししたか／マニュアルと違った点・改善の提案／ゲストからの質問・その他
- レビューは、反応にかかわらず全員にお願いする（満足した人だけに頼むのは Google の口コミのポリシー違反）。

## セットアップ（20分）

1. 共有アカウントで「NGT 手配ボード（台帳）」を開き、「拡張機能」→「Apps Script」。
2. `コード.gs` の中身をすべて消し、1ファイル版（`build.cjs` で作った `.gs`）を貼って保存。第1版の `Index` ファイルは左の一覧から削除する。
3. 関数 `setup` を選んで「実行」。承認の画面が出たら、共有アカウントで許可する（スプレッドシート・フォーム・ドライブ・メールの送信）。「Google で確認されていません」は「詳細」→「（安全ではないページ）に移動」。
   - 第1版のシートは「台帳（第1版）」などに名前が変わって残る（消さない）。
   - 「対応一覧」「台帳」「ツアー」「設定」「ログ」「完了報告」のシート、CSV の置き場フォルダ（マイドライブの「NGT手配ボード_CSV置き場」）、完了報告フォーム、トリガー（10分おきの更新・✓を付けたとき・フォームが送られたとき・19時の事前確認）ができる。
4. 設定シートの「キラナの通知先」「リールの通知先」に、実際のアドレスを入れる（試運用のあいだは自分だけでもよい）。
5. 共有する：スプレッドシートを、リールの担当者（Google アカウント）とキラナの担当者に「編集者」で共有する。CSV を自分のアカウントから入れる人には、置き場フォルダも共有する。
6. 完了報告フォームを社外のガイドが開けるか確かめる：フォームの「設定」→「回答」で「ninja-kabukitokyo.com のユーザーに限定する」がオフになっていること。オンのままにできない場合は、Google Workspace の管理者設定で外部の回答を許可する。
7. 第1版のウェブアプリ（入力画面）は使わないので、「デプロイを管理」からアーカイブしてよい。

## テスト（見本の予約で流れを体験する）

- メニュー「テスト：見本の予約を入れる」で、段階の違う見本の予約（TEST-01〜07、名前・連絡先は架空）と「テストの手順」のシートができる。手順の順に ✓ を付けたり、報告フォームを送ったりして、1件が完了するまでを試せる。
- テスト用の CSV（予約番号が `TEST-` で始まる架空の予約）を「CSVを取り込む」で入れると、取り込みも試せる。
- 見本は、触るまで期限切れの通知を送らない。
- 終わったら「テスト：見本の予約を消す」。案件IDか予約番号が `TEST-` で始まる行と「テストの手順」のシートが消える（手で書いた行は消えないので、自分で削除する）。

## 注意

- 台帳の左5列・時刻の列・「変更・注意」は、スクリプトが書く。手で書き換えると警告が出る。
- CSV は、キラナが書き出した2種類だけを入れる（ファイル名が `kiranah-resort-` と `tryhard-` で始まるもの）。中身で NGT／NKT を見分けられない CSV は「エラー」フォルダに移り、ログに残る。
- 1つの CSV で「消えた予約」が5件を超えたら、書き出しの誤り（期間・条件の違い）を疑い、自動ではキャンセルにしない。台帳の「変更・注意」に「要確認」と出る。
- お客様の情報は、このスプレッドシートとドライブの中だけに置く。リポジトリ（このフォルダ）には入れない。

## 開発者向け

- テスト：`node ops/ngt-board/test/run.cjs`（Google のサービスを偽物に置き換え、CSV の取り込みから完了までを確かめる。予約番号・氏名はすべて架空）
- 1ファイル版：`node ops/ngt-board/build.cjs 設定の初期値.json > 出力先.gs`。JSON は `{"キラナの通知先": "...", "リールの通知先": "..."}` の形。**アドレスが入るので、JSON と出力した .gs はリポジトリに入れない。**
- CSV の形（LINKTIVITY の予約一覧の書き出し、UTF-8・BOM付き）：`booking_id, agent_booking_id, status, activity_date, activity_time, plan_name, ota, participant_name, contact_info, unit_type1〜10, unit_quantity1〜10` などを使う。人数は unit_type に「子供」だけを含むものを子ども、それ以外を大人として数える。
- このフォルダは公開サイト（Astro）のビルドの対象外（`tsconfig.json` の exclude）。

# NGT 手配ボード（台帳）

LINKTIVITY の予約・キャンセルの通知メールを取り込み、予約1件を台帳の1行で管理する仕組みです。日時・人数の入力やリールへの発注が遅れると、担当者に催促が届きます。共有アカウント（info_ninja-go-ride@ninja-kabukitokyo.com）の Google スプレッドシートと Gmail の上で動きます。追加の費用はかかりません。

## できること・できないこと

| できること | しくみ |
|---|---|
| 新しい予約を台帳に載せる | 通知メールの予約番号・PLAN名・経路を5分おきに取り込み、「詳細待ち」で1行つくる |
| 詳細の入力を催促する | 期限（通知から2時間。夜間に届いたものは翌朝10時）を過ぎたら、メール（と LINE）で催促を繰り返す |
| リールへの発注メールを用意する | 入力したら、今と同じ書式の発注メールを Gmail の下書きに作る（設定で「自動送信」にもできる） |
| 発注・リールの返信を確かめる | 件名の案件ID（［NGT-0001］）で、送信済みメールとリールからの返信を探す。なければ催促する |
| キャンセルを反映する | 予約番号で台帳を照合。発注済みなら、リールへのキャンセルのメールを用意して、返信まで追いかける |
| NKT セットを取り込む | info@ninja-kabukitokyo.com から、セットの通知だけを共有アカウントへ転送して取り込む |
| 毎朝のまとめ | 9時に、対応待ちと3日以内のツアーを送る |

**できないこと**
- 日時・人数・代表者名は、通知メールに載っていないため、手で入力する（LINKTIVITY の管理画面に自動でログインして読み取ることはしない）。
- 日時の変更は、LINKTIVITY のシステムから通知が来ない（成立済みの予約の日時は変えられない仕様。Viator などでお客様が変えた場合は、LINKTIVITY の担当者からメールで連絡が来る）。そのときは画面で日時を直すと、リールへの【変更】メールを用意する。

## セットアップ（30分ほど）

### 1. スプレッドシートとスクリプト
1. 共有アカウントで Google スプレッドシートを新しく作り、名前を「NGT 手配ボード（台帳）」にする。
2. メニューの「拡張機能」→「Apps Script」を開く。
3. 最初からある `コード.gs` の中身をすべて消し、貼り付けて保存する。
   - **1ファイル版（おすすめ）**：`build.cjs` で作った `.gs` を1つ貼るだけ。画面の HTML と、宛先などの設定の初期値が入っている。
   - **2ファイル版**：このフォルダの `Code.gs` を貼り、左の「ファイル」の「＋」→「HTML」で名前を `Index` にして作って、`Index.html` を貼る。
4. 左の歯車（プロジェクトの設定）で、タイムゾーンを「(GMT+09:00) 日本標準時 - 東京」にする。
5. スプレッドシートを開き直すと、メニューに「NGT 手配ボード」が出る。「初期設定（最初に1回）」を押す（Apps Script の画面で関数 `setup` を選んで「実行」でもよい）。承認の画面が出たら、共有アカウントで許可する（Gmail の読み取りと送信、スプレッドシート、外部への接続）。「Google で確認されていません」と出たら「詳細」→「（安全ではないページ）に移動」で進む（自分たちで作ったスクリプトのため）。

`setup` を実行すると、シート（台帳・ツアー・設定・ログ）、Gmail のラベル、5分おきの取り込みと毎朝9時のまとめのトリガーができます。設定の「取り込み開始」には実行した時刻が入り、それより前の通知メールは取り込みません。

### 2. 設定シートを埋める（1ファイル版で初期値を入れてあれば、確かめるだけ）
| 項目 | 入れるもの |
|---|---|
| 通知先メール | 催促を受け取る人のアドレス（キラナ担当・企画担当）。カンマ区切り |
| リールの宛先 | 今の発注メールの宛先（リールのご担当者と共有アドレス） |
| 発注メールのCC | キラナ担当など |
| 発注のしかた | 最初は「下書き」。慣れたら「自動送信」 |
| 発注メールの件名の先頭 | 試運用のあいだは【試運用】 |

ほかの項目（期限・夜間・返信の期限）は、そのままで使えます。

### 3. ウェブ画面を公開する（入力の画面）
1. Apps Script の右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」を選ぶ。
2. 「次のユーザーとして実行」は「自分」。
3. 「アクセスできるユーザー」は次のどちらか。
   - **ninja-kabukitokyo.com 内の全員**：共有アカウントでログインしたブラウザからだけ開ける。いちばん安全。
   - **全員**：通知メールのリンクを、どのブラウザからでも開ける。リンクには推測できない鍵が付く。LINE をグループで使うときは、こちらが必要。Workspace の管理者設定で外部への共有を止めていると選べない。
4. 「デプロイ」を押す。スプレッドシートを開き直すと出るメニュー「NGT 手配ボード」→「一覧ページのリンクを表示」で、台帳の一覧ページのリンクが分かる。

### 4. Gmail の転送
- **NKT セット**：info@ninja-kabukitokyo.com の Gmail で、設定 →「転送と POP/IMAP」→「転送先アドレスを追加」で info_ninja-go-ride@ninja-kabukitokyo.com を追加し、届いた確認コードで承認する。続けてフィルタを作る。
  - From：`no-reply@linktivity.co.jp`
  - 含む：`ローカルツアーセット`
  - 処理：上で追加したアドレスに転送する
- **NGT の通知**（株式会社Kiranah Resort 宛て）が共有アカウントに直接届いていない場合は、届いている受信箱で同じように、From：`no-reply@linktivity.co.jp`、含む：`NINJA GO TOURS` のフィルタで転送する。
- 自動転送が管理者設定で止められている場合は、Google Workspace の管理コンソールで許可する（同じドメイン内への転送）。
- **NKT セットのプラン名を変えたら、このフィルタの文字も直す**。直さないと、セットの予約が取り込まれない。

### 5. 動作の確認
- メニュー「NGT 手配ボード」→「今すぐ通知メールを取り込む」。
- 「取り込み開始」より前の予約も入れたいときは、設定の「取り込み開始」を早めて（例：`2026-11-10 00:00`）、もう一度取り込む。
- 取り込んだメールには Gmail のラベル「NGT台帳/取込済」、読み取れなかったメールには「NGT台帳/取込不可」が付く。

## 毎日の使い方

1. **新しい予約**：「新しい予約：詳細を入力してください」が届く。リンクを開き、LINKTIVITY の管理画面で予約番号を検索して、日時・人数・代表者名・連絡先を写し、「保存して発注に進む」を押す。テスト予約（氏名が Test など）は「テスト予約として閉じる」。
2. **発注**：共有アカウントの Gmail の下書きに、リールへの発注メールができる。内容を確かめて送る（**件名の［NGT-0001］は消さない**）。5分以内に「返信待ち」になる。
3. **リールの返信**：リールが返信すると、自動で「手配済み」になる。期限までに返信がなければ催促が届くので、電話で確かめて「リールの返信を確認した」を押す。
4. **キャンセル**：自動で反映される。発注済みなら、キャンセルのメールの下書きができるので送る。まだ発注していなければ、何もしなくてよい。
5. **台帳にない予約のキャンセル**：この仕組みを入れる前の予約や、取り込めなかった予約。リールに手配していないか、今までの発注メールで確かめ、済んだら「確認した」を押す。
6. **日時・人数の変更**：LINKTIVITY の担当者から連絡が来たら、案件の画面で直して保存する。【変更】のメールの下書きができる。
7. **台帳のシートに直接書いてもよい**：「詳細待ち」の行に催行日・開始時刻・大人の人数を入れると、次の取り込みで発注に進む。

## 状態の一覧

| 状態 | 意味 | 次にやる人 |
|---|---|---|
| 詳細待ち | 通知を取り込んだ。日時・人数が未入力 | キラナ担当 |
| 発注待ち | 入力済み。リールへの発注メールがまだ送られていない | キラナ担当 |
| 返信待ち（発注済み） | 発注メールを送った。リールの返信待ち | リール |
| 手配済み | リールから返信があった | — |
| 催行済み | 開始から3時間たった | — |
| テスト予約 | テストとして閉じた | — |
| キャンセル（未発注） | 発注前にキャンセル。連絡は不要 | — |
| キャンセル（リールへ連絡待ち） | 発注済みの予約のキャンセル。リールへの連絡がまだ | キラナ担当 |
| キャンセル（リールの返信待ち） | リールにキャンセルを連絡した。返信待ち | リール |
| キャンセル（完了） | リールの確認がとれた | — |
| キャンセル（台帳になし・要確認） | 台帳にない予約のキャンセル | キラナ担当 |

## 期限と催促（設定シートで変えられる）

| 状態 | 期限 | 催促の内容 |
|---|---|---|
| 詳細待ち | 通知から2時間（夜間に届いたものは翌朝10時） | 詳細を入力してください |
| 発注待ち | 入力から30分 | 発注メールを送ってください |
| 返信待ち | 発注から24時間（催行まで48時間を切っていたら2時間） | 電話で手配を確かめてください |
| キャンセル（リールへ連絡待ち） | キャンセルから30分 | キャンセルを連絡してください |
| キャンセル（リールの返信待ち） | 連絡から24時間（直前なら2時間） | 電話で確かめてください |

- 期限を過ぎると、60分おきに催促する。夜間（22:00〜8:00）は送らない。
- 催行まで24時間を切った案件の催促は、件名に【至急】が付き、LINE にも送る。

## LINE の設定（任意）

LINE Notify は2025年3月に終わっているため、LINE公式アカウント（Messaging API）を使います。アカウントは Kiranah 名義で作ってください。

1. LINE公式アカウントを作り、Messaging API を有効にする。LINE Developers でチャネルアクセストークン（長期）を発行する。
2. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に `LINE_TOKEN`（トークン）を追加する。トークンは設定シートには書かない。
3. 送り先を決める。
   - **グループに送る**：LINE Developers の Webhook URL にウェブアプリの URL を入れ、「グループトーク・複数人トークへの参加を許可する」をオンにして、ボットをグループに招待する。グループの ID が自動で登録される（ウェブアプリのアクセスは「全員」が必要）。
   - **友だち全員に送る**：スクリプト プロパティに `LINE_TO` = `broadcast` を入れる。公式アカウントを友だち追加した人全員に届く。
4. 設定シートの「LINE通知」を ON にする。

LINE には、お客様の名前・連絡先を載せません（案件ID・ツアー・日時・リンクだけ）。無料プランは月に送れる数に上限があり、グループや友だち全員に送ると人数分として数えられます（最新の条件は LINE の案内で確認すること）。そのため、LINE には新しい予約、至急の通知、催促の1回目と3回ごとだけを送ります。

## 注意

- 件名の［NGT-0001］は消さない。リールの返信を見分けるのに使っている。
- リールが件名を変えて新しいメールで返信すると、返信として見分けられない。そのときは「リールの返信を確認した」を押す。
- LINKTIVITY の通知メールの書式が変わると「読み取れない通知」になる。届いたら、内容を見て台帳に手で足す。
- 一覧ページ・案件ページのリンクには鍵が付いている。社外に転送しない。
- 共有アカウントは2段階認証にし、パスワードを平文のメールで送らない。
- お客様の情報は、このスプレッドシートと Gmail の中だけに置く。リポジトリ（このフォルダ）には入れない。

## 開発者向け

- テスト：`node ops/ngt-board/test/run.cjs`（Google のサービスを偽物に置き換え、取り込みから発注・キャンセルまでを確かめる。予約番号・氏名はすべて架空）
- 1ファイル版を作る：`node ops/ngt-board/build.cjs 設定の初期値.json > 出力先.gs`。設定の初期値の JSON は `{"通知先メール": "...", "リールの宛先": "..."}` の形で、設定シートの項目名をキーにする。**宛先などが入るので、JSON と出力した .gs はリポジトリに入れない。**
- clasp で入れる場合は `appsscript.json` を使う。
- このフォルダは公開サイト（Astro）のビルドの対象外（`tsconfig.json` の exclude）。
